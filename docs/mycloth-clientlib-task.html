My Cloth Client Libraries

Technical task documentation and interview guide
Project: My Cloth AEM application | Date: 25 September 2026

1. Task Summary

The task was to configure global AEM client libraries for the My Cloth application. The client libraries provide reusable CSS and JavaScript to AEM pages, while the frontend build compiles Sass and JavaScript into deployable AEM assets.

RequirementImplementation
Define mycloth.baseConfigured in clientlib-base/.content.xml.
Define mycloth.siteConfigured in clientlib-site/.content.xml and generated by clientlib.config.js.
Brand paletteNavy #0f172a, Gold #c9a84c, and neutral Sass tokens.
TypographyAvenir Next with Helvetica and Arial fallbacks.
MinificationGCC processors in AEM metadata and production Webpack minimizers.

2. What Changed

Clientlib metadata

categories="[mycloth.base]"
cssProcessor="[default:none,min:gcc]"
jsProcessor="[default:none,min:gcc]"

The same processor configuration is used by mycloth.site. The base library embeds selected AEM Core Component libraries and the grid library. The site library depends on mycloth.dependencies and contains the generated site assets.

Frontend styling

_variables.scss is the central design-token file. _base.scss applies the tokens to the page, links, and form controls. main.scss imports the variables, base styles, component styles, and site styles.

$color-navy:       #0f172a;
$color-gold:       #c9a84c;
$color-neutral-50: #f8fafc;
$font-family:      "Avenir Next", "Helvetica Neue", Helvetica, Arial, sans-serif;

Build compatibility fixes

  • Updated postcss-loader configuration to use the v8 postcssOptions API.
  • Updated Maven frontend tooling from Node 16/npm 8 to Node 20/npm 10 because current dependencies use APIs such as toSorted().

3. Technical Architecture

Sass / JS source
ui.frontend/src
->
Webpack production build
npm run prod
->
AEM clientlib generator
clientlib.config.js
->
ui.apps clientlibs
/apps/mycloth/clientlibs

Webpack compiles Sass to CSS, bundles JavaScript, applies autoprefixing, and minifies production assets. The AEM clientlib generator copies the output into the ui.apps content package and writes clientlib metadata.

Page delivery flow

AEM page policy
->
Clientlib category
->
/etc.clientlibs proxy
->
Browser CSS/JS

The page policy includes the dependency and site categories. Page header/footer templates include the base category. AEM serves clientlibs through the proxy path so application code does not expose repository implementation paths directly.

Likely questions and answers

QuestionAnswer
What is an AEM clientlib?An AEM-managed collection of CSS, JavaScript, and resources. It has a category name, dependencies, processors, and a proxy URL used by pages.
Why separate base and site libraries?Base contains shared platform/component assets. Site contains project-specific styling and behavior. This keeps responsibilities clear and makes dependencies reusable.
Why use categories?Pages request stable category names instead of knowing physical asset filenames. AEM resolves dependencies and generates the final CSS/JS response.
How does minification happen?Webpack production mode minifies the generated bundle, and the AEM clientlib metadata also declares GCC processors for clientlib processing.
How did you troubleshoot the build?I followed the Maven error into the nested npm command, ran npm run prod directly, corrected the PostCSS v8 schema, then fixed the Node runtime mismatch revealed by toSorted().
How did you test it?I ran the frontend build, Maven verification, package installation, direct clientlib endpoint checks, and browser Network inspection on local author.
What remains unverified?Publish-specific runtime behavior, because no local publish instance was available. That should be checked in a publish SDK or deployment pipeline.
